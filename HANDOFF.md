## Recent Architecture Change: Guide Clusters

The old `relatedSlugs` architecture has been removed.

Related Decisions are now driven exclusively by the `clusters` array in:

``` text
lib/guides.ts
```

The relationship rule is:

> Two published guides are related when they share at least one cluster.

`getRelatedGuides()` automatically:

-   finds published guides sharing a cluster with the current guide,
-   excludes the current guide,
-   and applies the configured result limit.

There is no need to maintain reciprocal slug lists.

A guide can belong to multiple clusters when the editorial relationship
is genuine.

A guide with no meaningful current relationship should use:

``` ts
clusters: [],
```

Do **not** create a generic `misc` cluster merely to populate Related
Decisions.

## Guide #26 Decision-Check Lessons

The pre-listing inspection tool reinforced several useful design rules:

-   Decision checks should not force every user into a high/low binary.
-   A broad middle result can be appropriate when the evidence is
    situational.
-   Inputs that are logically contradictory should be mutually
    exclusive.
-   Reasons shown in the result must correspond to inputs the user
    actually selected.
-   A targeted specialist path should require an actual targeted
    concern, not merely selection of a "targeted" dropdown option.
-   Initial defaults should be neutral where possible.
-   Example/default inputs should not appear to be personalized advice
    before interaction.
-   Avoid manual `useMemo` when it creates React Compiler preservation
    errors without providing meaningful benefit.

These principles complement the durable calculator and decision-tool
guidance in `STYLE_GUIDE.md`.

3.  design the interactive tool only if it materially improves the

4.  build and QA the tool,
5.  build the complete guide,
6.  register it in `lib/guides.ts` with the appropriate cluster
    assignment and `lastModified`,
7.  run all three technical checks,
8.  perform visual and scenario QA,
9.  commit and push,
10. verify production and sitemap behavior.
